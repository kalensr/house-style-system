# Examples

Use these examples as patterns for review and revision.

## Contrast Scaffolding

Before:

```text
A checklist can remind me to separate facts from assumptions. It cannot do the thinking for me.
```

After:

```text
A checklist owns repeatable prompts. The writer owns the thinking.
```

## Generic Closing

Before:

```text
This framework paves the way for a brighter future of writing.
```

After:

```text
This framework gives reviewers a place to start.
```

## Weak Evidence

Before:

```text
AI writing is usually worse because it sounds generic.
```

After:

```text
AI-assisted drafts often need review for generic tone, weak evidence, and missing author judgment.
```

## Filler

Before:

```text
It is important to note that the system should be used thoughtfully.
```

After:

```text
Use the system thoughtfully.
```

## Human Review Boundary

Before:

```text
The style gate proves the document is ready.
```

After:

```text
The style gate shows the document avoided known style risks. Human review still owns truth, evidence, and recommendation quality.
```

## Observable Client Outcome

Before:

```text
Outcome: an implementation brief, role matrix, workflow map, architecture
decision record, recovery baseline, and acceptance evidence.
```

After:

```text
The service owner and operations lead agree who may publish a release, what the
complete release packet contains, and what the team does when the service is
unavailable. They verify the decision in a working demonstration: one person
publishes a release, another opens the same release, and the team restores the
test record after deletion. The role matrix, workflow map, and recovery record
preserve the decisions made during that demonstration.
```

Why the revision works:

- it keeps the underlying artifacts;
- it makes the client and operators the subjects;
- it shows the changed working state;
- it gives the reader visible proof of completion; and
- it connects documentation to the result instead of presenting documents as
  the result.

Do not copy names, workflows, or acceptance conditions from this synthetic
example into a real engagement. Build the outcome from that engagement's
sources.
